НОВЫЙ СБОЙ И ПРИЧИНА

Новый отчёт: Description: Saving replay file; IOException:
Expected root tag to be a CompoundTag, was 7.
Стек: OpenNBT -> Packet.Reader.readNBT -> PacketConfigRegistries ->
RegistriesBuilder -> ReplayInputStream -> MarkerProcessor.

Сбой воспроизведён настоящими библиотеками ReplayStudio/OpenNBT из JAR на пакете
реестров с корневым ByteArrayTag (тип 7). Старый readNBT допускал только CompoundTag,
хотя структуры данных реестров и запись пакетов уже используют общий тип Tag.
В актуальном upstream ReplayStudio чтение также возвращает общий Tag:
https://github.com/ReplayMod/ReplayStudio/blob/a2e312635cd305d0dd57218b810c6088b59c18b0/src/main/java/com/replaymod/replaystudio/protocol/Packet.java

ИСПРАВЛЕНИЕ РЕВИЗИИ 4

- Packet$Reader: добавлены два перегруженных readAnyNBT и приватный readAnyTag,
  использующие TagRegistry. Сохранены версия-зависимое имя корневого тега,
  обработка пустого тега и старый сжатый формат. Старые readNBT с возвращаемым
  CompoundTag сохранены без изменения поведения для остальных потребителей.
- PacketConfigRegistries: чтение отдельных значений реестра через readAnyNBT.
- Registries: то же для восстановления значений из внутреннего кэша.
- PacketEnabledPacksData: то же для данных известных пакетов.

Изменены только эти четыре класса относительно ревизии 3. Данные не отбрасываются,
ошибки повреждённого NBT не подавляются. Записывающий код уже поддерживает Tag.
Изменения выполнены ASM с корректными дескрипторами, кадрами стека и пересчётом
максимального стека. Метод декодера компилируется JDK из исходника внутри Patch.java
и переносится в Reader. Новых внешних библиотек или классов в JAR не добавлено.
Вложенный OpenNBT не изменён: это избегает изменения общей библиотеки других модов.
